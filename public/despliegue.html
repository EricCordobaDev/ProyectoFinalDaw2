Manual Interactivo de Despliegue: Gamelive (Laravel y React)

Un manual paso a paso para que podamos desplegar nuestra aplicación Gamelive (Laravel y React) en un servidor de producción.

1. Requisitos del Servidor

Antes de comenzar, debemos asegurarnos de que nuestro servidor tenga lo siguiente instalado y configurado:

  • Servidor Web: Nginx que es generalmente preferido para rendimiento.
  • PHP: Versión compatible con nuestro proyecto Laravel (ej., PHP 8.x) y las extensiones necesarias (ej., php-fpm, php-mbstring, php-xml, php-bcmath, php-curl, php-mysql o php-pgsql).
  • Base de Datos: MySQL, PostgreSQL, u otra base de datos compatible.
  • Composer: Gestor de dependencias de PHP.
  • Node.js y npm: Para construir la aplicación React.
  • Git: Para clonar nuestro repositorio.
  • SSH: Acceso al servidor.

2. Configuración del Servidor (Ejemplo con Nginx y Ubuntu)

2.1 Actualizar el Sistema

sudo apt update
sudo apt upgrade

2.2 Instalar Nginx

sudo apt install nginx
sudo ufw allow 'Nginx Full' # Si usamos UFW firewall

2.3 Instalar PHP y Extensiones

sudo apt install php8.2-fpm php8.2-mysql php8.2-mbstring php8.2-xml php8.2-bcmath php8.2-curl php8.2-zip

(Reemplazamos php8.2 con la versión de PHP que necesitemos)

2.4 Instalar MySQL/PostgreSQL

Para MySQL:

sudo apt install mysql-server
sudo mysql_secure_installation # Seguimos las instrucciones para asegurar nuestra instalación

Para PostgreSQL:

sudo apt install postgresql postgresql-contrib
sudo -u postgres psql # Para acceder a la consola de PostgreSQL
# CREATE USER your_user WITH PASSWORD 'your_password';
# CREATE DATABASE your_database WITH OWNER your_user;
# \q

2.5 Instalar Composer

php -r "copy('https://getcomposer.org/installer', 'composer-setup.php');"
php composer-setup.php
php -r "unlink('composer-setup.php');"
sudo mv composer.phar /usr/local/bin/composer

2.6 Instalar Node.js y npm

curl -fsSL https://deb.nodesource.com/setup_lts.x | sudo -E bash -
sudo apt-get install -y nodejs

3. Preparación del Proyecto en el Servidor

3.1 Clonar el Repositorio

Navegamos hasta el directorio donde deseamos alojar nuestro proyecto (ej., /var/www/).

cd /var/www/
sudo git clone https://github.com/EricCordobaDev/ProyectoFinalDaw2.git; gamelive
cd gamelive

3.2 Instalar Dependencias de Laravel

composer install --no-dev --optimize-autoloader

3.3 Configurar el Archivo .env

Copiamos el archivo de ejemplo y lo editamos con nuestras credenciales de base de datos y otras configuraciones de producción.

cp .env.example .env
sudo nano .env # O nuestro editor preferido

Debemos asegurarnos de configurar:

  • APP_ENV=production
  • APP_DEBUG=false
  • APP_URL=http://gamelive.somontanosocial.com
  • DB_CONNECTION, DB_HOST, DB_PORT, DB_DATABASE, DB_USERNAME, DB_PASSWORD

3.4 Generar la Clave de Aplicación

php artisan key:generate

3.5 Ejecutar Migraciones de Base de Datos

php artisan migrate --force

3.6 Enlazar el Almacenamiento

php artisan storage:link

4. Construir la Aplicación React

El proceso de construcción de React puede hacerse en nuestra máquina local y luego subir los archivos build al servidor, o directamente en el servidor. Hacerlo en el servidor es a menudo más sencillo si tenemos Node.js instalado allí.

4.1 Instalar Dependencias de Node.js

Debemos asegurarnos de estar en el directorio raíz de nuestro proyecto Laravel (donde está el package.json de React).

npm install # O yarn install

4.2 Construir la Aplicación React

npm run build # O yarn build

Esto creará una carpeta build (o dist, dependiendo de nuestra configuración de React) dentro de nuestro directorio public de Laravel. Laravel servirá estos archivos estáticos.

5. Configuración del Servidor Web (Nginx)

Ahora, configuramos Nginx para que sirva nuestra aplicación Gamelive (Laravel y React).

5.1 Crear un Bloque de Servidor para Nginx

sudo nano /etc/nginx/sites-available/gamelive.somontanosocial.com

Pegamos la siguiente configuración (ajustamos el dominio y la ruta de nuestro proyecto):

server {
    listen 80;
    server_name gamelive.somontanosocial.com www.gamelive.somontanosocial.com;
    root /var/www/gamelive/public; # Ruta a la carpeta public de Laravel

    add_header X-Frame-Options "SAMEORIGIN";
    add_header X-XSS-Protection "1; mode=block";
    add_header X-Content-Type-Options "nosniff";

    index index.html index.htm index.php;

    charset utf-8;

    location / {
        try_files $uri $uri/ /index.php?$query_string; # Para rutas de Laravel
        # Si nuestro React Router está en modo historial, añadimos esto para que React maneje las rutas:
        # try_files $uri $uri/ /index.html; # Para rutas de React (asegurémonos de que index.html esté en public)
    }

    location ~ \.php$ {
        fastcgi_pass unix:/var/run/php/php8.2-fpm.sock; # Ajustamos la versión de PHP-FPM
        fastcgi_index index.php;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
    }

    location ~ /\.(?!well-known).* {
        deny all;
    }
}

Nota sobre try_files:

  • Si nuestra aplicación React se sirve desde un subdirectorio o solo usamos React para una parte de la aplicación, y Laravel maneja la mayoría de las rutas, la primera try_files es suficiente.
  • Si nuestra aplicación React es una SPA (Single Page Application) y se encarga de todo el routing del frontend, la segunda try_files $uri $uri/ /index.html; (descomentémosla) es crucial para que todas las rutas no encontradas por Nginx se redirijan a index.html de React. Asegurémonos de que nuestro index.html (generado por el build de React) esté en la carpeta public de Laravel.

5.2 Habilitar el Bloque de Servidor

Creamos un enlace simbólico desde sites-available a sites-enabled:

sudo ln -s /etc/nginx/sites-available/gamelive.somontanosocial.com /etc/nginx/sites-enabled/

5.3 Probar la Configuración de Nginx y Reiniciar

sudo nginx -t
sudo systemctl restart nginx

6. Permisos de Archivos y Directorios

Es crucial establecer los permisos correctos para que Laravel pueda escribir en los directorios storage y bootstrap/cache.

sudo chown -R www-data:www-data /var/www/gamelive
sudo chmod -R 775 /var/www/gamelive/storage
sudo chmod -R 775 /var/www/gamelive/bootstrap/cache

(Asegurémonos de que www-data sea el usuario de nuestro servidor web, puede variar en otros sistemas operativos)

7. Configuración de HTTPS

Usamos Certbot para obtener un certificado SSL/TLS gratuito de Let's Encrypt.

sudo apt install certbot python3-certbot-nginx
sudo certbot --nginx -d gamelive.somontanosocial.com -d www.gamelive.somontanosocial.com

Seguimos las instrucciones en pantalla. Esto configurará automáticamente Nginx para usar HTTPS.

8. Verificación Post-Despliegue

  • Abrimos nuestro navegador y visitamos http://gamelive.somontanosocial.com o https://gamelive.somontanosocial.com.
  • Verificamos que tanto el frontend de React como las rutas de la API de Laravel funcionen correctamente.
  • Revisamos los logs de Laravel (storage/logs/laravel.log) y los logs de Nginx (/var/log/nginx/error.log) si encontramos problemas.

9. Solución de Problemas Comunes

  • Página en blanco o "Whoops, something went wrong":
    • Revisamos los permisos de storage y bootstrap/cache.
    • Verificamos que APP_DEBUG=false y APP_ENV=production en .env.
    • Revisamos los logs de Laravel.
  • Errores 500 del servidor:
    • Permisos incorrectos.
    • Error de sintaxis en la configuración de Nginx/Apache.
    • Problema con la conexión a la base de datos (revisamos .env).
    • Revisamos los logs de PHP-FPM.
  • Rutas de React no funcionan (404):
    • Nos aseguramos de que try_files $uri $uri/ /index.html; esté correctamente configurado en Nginx/Apache.
    • Verificamos que el archivo index.html de React esté en el directorio public de Laravel.
  • Archivos estáticos (CSS/JS) de React no cargan:
    • Verificamos que npm run build se haya ejecutado correctamente y que los archivos estén en public/build (o donde nuestra configuración de Webpack/Vite los ponga).
    • Revisamos las rutas en nuestro index.html de React.
    • Nos aseguramos de que Nginx/Apache esté sirviendo correctamente los archivos estáticos desde el directorio public.
  • Errores de CORS:
    • Nos aseguramos de que nuestra configuración de CORS en Laravel (config/cors.php y el middleware) permita las solicitudes desde nuestro dominio de frontend.
